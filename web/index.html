    Tune slots

    A node's slot count is how many requests it serves at once. More slots buy throughput until the GPU is saturated, then buy only latency. Tuning loads the model at each count, measures, and recommends one per node: the answer is a fact about each machine, so the fleet is tuned side by side.

    Agent and chat benchmarksrun from a terminal

    Two longer benchmarks drive the cluster with real workloads and compare routing methods: SWE-bench Verified tasks through a coding agent (long conversations, heavy prompt reuse), and Aider's polyglot exercises (short tasks at a high request rate). They need Python, a container and an hour or more per mode, so they run from the repository, not this page.

    bench/swe/setup.sh && bench/swe/sequence.sh <run> router tuned
    bench/aider/setup.sh && bench/aider/sequence.sh <run> router tuned

    Set SWE_ENTRYPOINT, SWE_AGENT_BASE and SWE_CONTROL_ADDR first; bench/swe/README.md and bench/aider/README.md have the details.
